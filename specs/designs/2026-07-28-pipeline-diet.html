Design Brief · 2026-07-28

The instruction stack vs. /ship

How the CLAUDE.md layers on this machine cooperate with — and fight — the ship pipeline, and what the Fable 5 prompting guidance changes.

The verdict: the architecture is right — global taste, plugin process, per-repo facts — but the layers have drifted into 4 direct contradictions, ~7 duplicated rule-sets, and one live dial that the skill files no longer describe. And the Fable 5 guidance lands squarely on ship's biggest file: "Skills developed for prior models are often too prescriptive for Claude Fable 5 and can degrade output quality." The pipeline skill is 7,800 words with a prohibition every 110 words — much of it steering behavior Fable now does by default.

The move: resolve the 4 contradictions (3 are one-line edits, 1 is your call), put ship's per-repo knowledge into a small "ship contract" section in each repo's CLAUDE.md instead of hardcoding homezero into the global plugin, and put the pipeline skill on a Fable 5 diet — keep the machine contracts byte-exact, compress the behavioral steering into short principles, move the war stories to an appendix.

What's genuinely working

  • The one declared contract works. Ship names exactly one CLAUDE.md dependency — the standing stack, repo file overrides — and it matches the global file exactly. "The plugin is the process; your stack is you" is the right seam.
  • homezero is the model case. Its AGENTS.md names /ship as the flow, declares the CI gate, npm-only, deploy lanes, and the prod-send footgun. When ship runs there it has everything.
  • verify is already Fable-5-shaped. The guide's #1 scaffolding rec — fresh-context verifier subagents over self-critique — is verify's founding axiom.
  • The machine contracts are real infrastructure. Status line, shipboard, and FleetView parse them. These are the parts that must survive any rewrite byte-exact.

What's rotting

  • cells + wells are dead (Pete-confirmed) but still instrumented as alive: cells/CLAUDE.md sits in the active Projects tree, and the cells and wells skills are still registered globally — every session carries triggers for infrastructure that no longer exists.
  • notes/CLAUDE.md points at a nonexistent ~/Projects/CLAUDE.md and still lists wells/cells as active projects.
  • Zero/CLAUDE.md names two in-flight worktrees that are gone, and half-duplicates homezero's deploy-lane table (already drifting).
  • imessage/CLAUDE.md has a plaintext password in it.
  • buzz documents that Tauri cargo fmt fails inside git worktrees — a landmine directly under the worktree-always rule if /ship ever fires there. Nothing connects the two facts.

3 · What the Fable 5 guidance changes

The platform doc (the "new ways of prompting" — this is the written form of what Thariq's been saying) has one recommendation aimed straight at this setup:

"Refactor existing prompts and skills. Skills developed for prior models are often too prescriptive for Claude Fable 5 and can degrade output quality. Review and consider removing older instructions if default performance is better."

Pipeline SKILL.md is the poster child: 70 "never"s, ~176 bold spans, 18 rules that are incident post-mortems turned into permanent prose. The guide's counter-pattern: one short principle now steers what used to take an enumerated list — instruction-following is strong enough that listing every banned behavior is worse than stating the intent.

Three-way triplication

Several behaviors are now stated three times — in the Fable harness system prompt, in the global CLAUDE.md, and again in ship: act-don't-overplan, evidence-grounded status reports, pause-only-for-genuine-input, brevity. The harness copy is maintained by Anthropic and always current; the other two copies are now redundancy that can only drift.

Other guide items that map here

  • Memory: the guide's per-lesson-file pattern is already your harness memory + router ledger + ship-retro issues — three systems. The failure mode showed up already: a memory changed the engine dial and no skill file followed. Design rule: a memory that changes a dial triggers a skill edit (the retro path exists for exactly this; use it).
  • Reasoning echo: ship's "log why" ledger rows are fine (decision logs, not reasoning transcripts) — nothing here trips the reasoning-extraction refusal category. One less migration worry.
  • Effort: router's "xhigh is the floor" was written for codex; with Fable driving, the guide says lower efforts often beat old-model xhigh — the all-Fable decision changes the economics the ladder was built on.

4 · Target architecture

One fact, one layer. Each layer states only what it uniquely knows; lower layers reference upward, never restate.

  • Global CLAUDE.md — taste and cross-repo invariants only. Drops what the Fable harness now ships (autonomy, evidence-grounding). Gains two one-liners: machine-facing plans may be markdown; the EXPRESS merge ruling (whichever way you call it).
  • ship plugin — the process spine + machine contracts + environment-fact appendix. Loses: restated global rules, restated dial, homezero hardcoding (7 mentions), stale billing claim, behavioral steering Fable does natively. Gains: an explicit "overrides superpowers brainstorming/TDD on autonomous lanes" line.
  • Project CLAUDE.md — a small "ship contract" section, the real design idea here. Ship currently knows homezero by name; instead every shippable repo declares:
    • gates: the test/build commands that must be green
    • lanes: deploy commands per lane (or "none")
    • preview: how to provision an isolated backend (the clobbering-bug seam)
    • verify-auth: the test-auth path verify may use
    • ship: no — for van, mayor-pete, notes, paonia/PKAI, so the pipeline declines cleanly instead of improvising
    homezero already has all of this in prose; this just names the seam so the plugin reads it instead of embedding it. buzz's contract would carry its worktree-breaking fmt gotcha where ship would actually see it.
  • Memories/ledger — observations and dial history; any standing change flows into the owning skill file within the run that made it.
