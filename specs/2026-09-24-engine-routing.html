Ship engine routing

Opus 5.5 drives /ship now. Each BUILD task goes to the model its difficulty earns, and Jev, a fast classifier, measures that difficulty. Fable reviews the plan before anything is built and the whole branch before it merges. Every task's outcome goes into a ledger, so after one real build we tune the split from numbers.

Pete, 2026-09-24. All models at high effort. The Codex version is simpler: Astra does everything.

The BUILD ladder

Tasks are ranked against the rest of the same plan, not scored against a fixed bar, so every plan splits the same way.

How we judge it

Every accepted task appends one line to ~/.claude/ship-ledger.jsonl: engine, Jev score, minutes, fix rounds, whether the gates passed first try, and the driver's verdict. After the first build on this ladder, route.py report gives one table by engine and difficulty, and we move the cuts from it.

Codex version

Astra drives, writes the plan, builds every task, and a fresh Astra context reviews the plan and the branch. No Jev, no Anthropic models, high effort throughout. Its stage marker is now one line, so the status line reads it.

Why Sol left the ladder

Same brief, both at high effort: Sol 81 s, Astra 91 s, both passed 10/10. Sol writes about twice as fast, but reading files and running tests set a task's wall time, so the 6x never showed up. It comes back only if the ledger shows generation-heavy tasks where it would pay.

Risks worth watching
  • Fable quota: a quarter of BUILD plus two reviews. On a 12-task plan that is 3 tasks.
  • Sandbox asymmetry: only Astra cannot start a local server, so its server tests are expected failures. The ledger's first-pass rate reads Astra's gates after the driver's own run, not the sandbox's.
  • Tiny plans: a 1-task plan sends that task to Fable, because it is the hardest by rank. Mark small tasks (inline).
